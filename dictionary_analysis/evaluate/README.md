# Block-pruning evaluator

Standalone Rust executable. It reads exported terms and preserves every original block boundary. It does not modify Tantivy or its SSTable library.

## Reproduce

From the repository root:

```sh
cargo test --release --locked --manifest-path dictionary_analysis/evaluate/Cargo.toml
cargo run --release --locked --manifest-path dictionary_analysis/evaluate/Cargo.toml -- \
  KH4Y_01M5MTJQ3SVHDTK2W3XCB5/message_analysis \
  KH4Y_01M5MTJQ3SVHDTK2W3XCB5/message_analysis 2000000
```

Arguments: input directory, output directory, optional transition budget per solver (default 2,000,000). The crate has its own workspace and lockfile. It needs `serde` and `serde_json`.

Input:

- `terms.bin`: repeated unsigned 32-bit little-endian length followed by raw full key bytes.
- `blocks.jsonl`: `block_id`, `first_ordinal`, `term_count`, `byte_start`, `byte_end`, `terms_offset`, nullable `lower_hex`, `upper_hex`, `first_hex`, `last_hex`, and `existing_candidates` keyed by the seven queries. The lower bound is the previous separator, exclusive. The upper separator is inclusive. The first block has no lower bound.

Output:

- `evaluate_blocks.jsonl`: candidates and budget fallbacks for every method/query/block, exact matching term counts, compressed ranges, numeric classification, prefix bytes, and summary cardinalities.
- `evaluation.json`: aggregate results, numeric/other breakdown, metadata sizes and distributions, semantics, and false-negative validation.

A block is numeric when **every** term is nonempty ASCII `[0-9]+`. Mixed blocks are counted as other. Exact numeric-term counts and mixed-block counts are also reported. An additional, explicitly labeled partition compares `numeric_majority` (at least half its terms are numeric) with `other_than_numeric_majority`. The exported data has no purely numeric original blocks, so this partition makes the numeric-region comparison useful without changing block boundaries.

## Methods

All query matching is case-sensitive on raw bytes. `*` accepts every byte, including NUL, invalid UTF-8, and newline. Query order is `[*a*, *ab*, *traa*, *X, *x, *player*, *ms*]`. Queries at indices 0–2 and 5–6 are substrings. Only indices 3–4 are suffixes (`X` and diagnostic `x`). The tests explicitly check appended substring matching inside arbitrary bytes and case sensitivity.

| Method | Model |
|---|---|
| `oracle` | Scan every actual term. |
| `existing` | Current index pruning exported by the extractor. |
| `bounds_length` | Exact query-automaton intersection with the lexicographic interval and full-byte min/max length. |
| `bounds_length_bytes` | Also restrict every byte to the whole-block byte alphabet. |
| `bounds_length_literal_pairs` | Also require every literal bigram to occur in the whole-key pair set. |
| `bounds_length_literal_trigrams` | Also require every literal trigram to occur in the whole-key triple set. This is an expensive exact-summary reference model. |
| `bounds_length_pair_graph` | Product with the whole-key directed byte-pair graph. Every adjacent generated byte pair must be present. |
| `bounds_prefix_bytes` | Consume the free prefix derived from separator bounds, then restrict remainder bytes. |
| `bounds_prefix_pair_graph` | Also require remainder-internal adjacent pairs to be present. |
| `term_prefix_bytes` | Use actual term LCP instead, with explicit prefix storage cost. |
| `term_prefix_pair_graph` | Actual term LCP and remainder pair graph. |

The free prefix is `LCP(lower, upper)`, or empty for the first block. Every key in the interval has this prefix. The actual term LCP is a stored summary, which can be longer.

The solver state is `(query DFA state, lower/upper comparison flags, full byte length, previous remainder byte)`. Prefix bytes are consumed into the query and bound automata. The first remainder byte has no pair restriction. This preserves literals crossing the prefix boundary. Remainder-only summaries never receive unsafe whole-literal gram tests.

The finite-length product search is exact when completed. A transition-budget exhaustion conservatively retains the block and is counted in each result. State and byte traversal are ordered, so budget results are reproducible. The cheap preliminary DFA reachability test only rejects when the query cannot be reached using the remainder alphabet. Whole-key literal byte/gram tests are necessary conditions, applied only to whole-key sets.

The tests use independent brute-force word enumeration and direct byte matching. They exhaust every directed pair graph on a two-byte alphabet, alphabet subsets, small intervals, and all small min/max lengths. Fixed-seed randomized tests cover full and remainder summaries, free and stored prefixes, empty keys/remainders, byte values 0 and 255, variable lengths, and prefix-crossing matches. Full-256-byte-alphabet tests independently check interval/length cases. A zero-budget test checks conservative fallback.

## Size model

These are **incremental, uncompressed metadata estimates**. Existing index storage is shared and excluded. Runtime Rust hash tables are not serialized size estimates.

- Full-key min/max length: two unsigned LEB128 varints per block.
- Byte alphabet: 32 bytes per block.
- Free prefix: zero bytes, derived from the existing bounds.
- Actual term prefix: unsigned LEB128 prefix length plus raw prefix bytes per block.
- Sparse exact pair payload: `2D` bytes for `D` distinct byte pairs.
- Alphabet-packed exact pair bitmap: `ceil(k*k/8)` bytes for alphabet size `k`. Byte ranks come from the already charged 32-byte alphabet mask.
- Adaptive pair payload: smaller of sparse and packed (ties select packed).
- Every modeled pair layout additionally charges a one-byte format tag per block, unsigned LEB128 distinct-pair count per block, and an array of `N+1` 64-bit offsets. The count is retained in the common record format even when derivable from the packed representation.
- Fixed full-alphabet pair bitmaps are also reported at 8,192 bytes per block.
- Exact triples: `3T` raw payload bytes, unsigned LEB128 distinct-triple count, and a separate `N+1` 64-bit offset array. Triple sizes augment the adaptive pair model. Exact triples are a useful expensive oracle, not a claim of a cheap practical summary.

Full and remainder alphabet, pair, triple, prefix, and length distributions include histograms and quantiles. No allocator, alignment, index framing, or compression benefit is assumed.

Retained compressed data bytes are the sum of `byte_end-byte_start` for candidate blocks, with **no hole coalescing**. They model original compressed block ranges. They are not measured latency, read requests, or physical I/O. Metadata must be considered alongside these retained bytes. Solver transition counts describe terminal method searches, not end-to-end evaluation CPU cost.
